## 1. 功能描述

### 1.1 核心体验
用户用自然语言描述症状（可多轮补充），Agent 完成：
1. **症状确认**：追问澄清（"头痛多久了？还发烧吗？"），把口语整理成结构化症状清单；
2. **推理**：调用工具得到疾病概率排序、相关症状、UMLS 详情；
3. **解释**：用 RAG 回答"为什么会是这个病、严不严重、要不要去医院、挂什么科"；
4. **输出**：一份结构化诊断报告（含概率、依据、建议、免责声明）。

### 1.2 对话示例（验收用例）
```
用户：我头痛两天了，还有点发烧，浑身没劲
Agent：收到～ 我再确认两点：有没有咳嗽/喉咙痛？体温大概多少？
用户：有点咳嗽，38度左右
Agent：好的，正在分析…
       🔹 已识别症状：头痛(C0018817)、发烧(C0015967)、咳嗽(C0006425)、乏力(C0015677)
       🔹 可能疾病（按概率）：
         1. 支气管肺炎（Bronchopneumonia）60.4% —— 常见症状：咳嗽、发热
         2. ……
       🔹 建议：症状持续超过 3 天或出现呼吸困难，请及时就医。
       ⚠️ 以上由 AI 生成，仅供参考，不构成医疗建议。
```

### v0.1 系统提示词（示例，先跑起来再迭代）
```
你是"医疗诊断助手"，一名面向普通用户的症状自查助手。
能力边界：
1. 你只能基于用户描述的症状和知识库/工具结果做"可能性排序"，不能确诊、不能开药、不能替代医生。
2. 出现胸痛、呼吸困难、意识不清、大出血等急症关键词时，直接建议拨打 120 或去急诊，不要继续追问。
输出规范：
1. 先给出"已识别症状（含 CUI）"，不确定的用追问澄清，不猜。
2. 疾病结果必须附概率，并说明"只是可能性排序"。
3. 每条结论末尾带：⚠️ 仅供参考，不构成医疗建议。
4. 用户情绪激动或坚持要"确诊/开药"时，礼貌说明边界并建议线下就医。
工具：validateSymptom / predict / sySuggest / getDetails（按需调用，不要编造结果）。
```

## 3. 评估指标定义

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 症状识别率 | 用户口语症状被正确映射为 CUI 的比例 | ≥ 85% |
| 报告完整率 | 一次会话产出完整报告（预测+建议+免责）的比例 | ≥ 90% |
| Top3 命中 | 离线评测集中真实疾病出现在 Top3 的比例 | 基线待测 |
| 幻觉率 | 输出不存在于知识库/工具结果的疾病或解释的比例 | ≤ 2% |
| 降级率 | 触发降级/转人工策略的比例（应 < 10%） | 记录 |
| 用户采纳率 | 用户按建议行动（复述/点击/收藏）的比例 | 追踪 |
| 拒答正确率 | 该拒答时（急症/处方/确诊）正确拒答的比例 | ≥ 95% |

**评测方式**：50~100 条典型病例离线集 + 线上日志回流 + 每周人工抽检 20 条。

## 4. 置信度阈值（分档行为）

以 predict 输出的最高疾病概率为基准：

| 档位 | 条件 | Agent 行为 |
| --- | --- | --- |
| 高置信 | 最高概率 ≥ 50% 且无矛盾症状 | 展示 Top3，正常解释与建议 |
| 中置信 | 30% ≤ 最高概率 < 50% | 展示 Top5，强调"可能性排序"，建议补充症状或就医 |
| 低置信 | 最高概率 < 30% 或症状相互矛盾 | **不硬下结论**，提示"信息不足"，建议描述更完整或线下就医 |
| 急症触发 | 命中急症关键词 | 直接建议 120/急诊，停止诊断流程 |

## 5. 降级策略

| 故障 | 降级方案 |
| --- | --- |
| LLM 不可用 / 超时 | 降级到 V1 一键诊断管线（确定性接口，仍可出报告） |
| 工具接口失败 | 提示"部分功能暂不可用"，保留已成功的部分 |
| 模型答非所问 / 连续 2 次异常 | 重试 1 次 → 仍异常则转 FAQ 或人工客服 |
| 输入无法理解（乱码/非症状） | 引导用户用"哪里不舒服 + 多久了 + 其他症状"的模板描述 |
| 高风险对话 | 立即转人工/就医建议（见 SOP） |

## 6. 边界清单（模型不能做什么）

- ❌ 不能确诊任何疾病（只做可能性排序）
- ❌ 不能开药、改药、停药
- ❌ 不能处理急症、创伤、中毒（直接建议急诊）
- ❌ 不能回答超出症状自查范围的问题（如保险、法律、心理咨询需转接）
- ❌ 不承诺准确率；不把概率结果表述为事实
- ❌ 不保存、不上传可识别个人身份的医疗数据（默认本地/脱敏）

## 7. 人机协作 SOP（什么时候转交人工）

| 触发条件 | 动作 |
| --- | --- |
| 命中急症关键词 | 建议 120/急诊，会话结束 |
| 低置信（<30%） | 建议补充信息；仍低 → 建议线下就医 |
| 用户坚持要求确诊/开药 | 说明边界，建议挂号对应科室 |
| 用户情绪激动 / 疑似心理危机 | 转人工或心理援助热线 |
| 用户主动要求"联系真人" | 提供人工入口（挂靠医疗机构的客服/分诊） |

## 8. 数据、隐私与合规

- 数据源：UMLS（需 NLM 授权）+ 公开疾病-症状数据 + 用户输入（脱敏）。
- 隐私：默认本地部署/私有化；用户对话不做训练集（除非明确授权）。
- 合规：显著免责声明；产品定位"辅助自查"，面向 B 端销售时配合医疗机构合规审查。

## 9. 上线与灰度

1. 内部评测集达标（幻觉率 ≤2%、急症拒答正确率 ≥95%）→ 内测；
2. 灰度 10% 用户 2 周，看降级率与用户采纳率；
3. 全量后每周抽检 + 指标看板（报告完整率/降级率/投诉率）。
